# 音乐库 v0.7.0：结构、迁移与使用

本轮依据 Step Six 的讨论内容实施。实际工程以现有身份、Scope、来源、权限及不可变历史机制为基础，不重新安装个人工作区。

## 现状审计

升级前本机曲库只有一条 Work 和一条 Person（用户确认是测试用贝九与贝多芬），已有一条作者关系、五条音乐操作历史。没有 Recording、Release、Track、Review、Genre 关联或特别库成员数据。两条实体保留原 ID、修订及来源，不创建推测的录音、发行或演奏人员。

原模型已有独立作品、录音、发行与音轨表，问题在于浏览以发行和五星为入口、Genre 可编辑在任意对象上、资料字段不足、人物关系单一、评分体系只有五星。旧 Album 在当前模型中使用 Release，未发现需要将 Album 改成 Work 的数据。

## 关系模型

| 实体 | 含义与关系 |
| --- | --- |
| Work | 完整音乐作品；多位作者、多 Genre、编号、别名、资料与个人记录；多乐章不会自动拆成作品 |
| Recording | 具体演绎版本；多对多关联 Work，独立演出人员、日期、地点和个人评分 |
| Release | 具体发行；封面、日期、编号、条码、厂牌、出版商、介质、版本及完整 Track；同一 Recording 可多次收录 |
| Track | 有序的发行音轨；保留稳定 ID，可修改位置、时长、关联录音、作品及具体参与者；追加曲目不会替换旧音轨 |
| Person / Group / Organization | 独立人物及组织；多角色、别名、说明、头像和有日期/来源的实体关系 |

所有关联使用 ID；名称相同不表示同一实体。再次发行时应关联已有 Recording，不重复新建录音。没有自动联网推断或按名称合并。

`music_profiles` 保存扩展资料；`music_relation_details` 保存成员、历史成员、历届指挥、子组织、合作等关系的日期及来源。未知日期可留空。

`music_work_paths` 沿实际 Work/Recording 关系及 Release 的 Track 容纳关系查找作品；`music_effective_genres` 动态连接作品 Genre。修改作品分类后，录音及发行的查询即时更新；同一发行出现在多个分类仍只有一条实体。历史非作品 Genre 关联作为 `legacy_genres` 保留，不擅自移到未知作品；新写入只允许在 Work 上设置 Genre。Genre、人物角色、私人音乐标签、记忆标签分别管理。

## 浏览与编辑

顶部只有录音库、作品库、人物/组织库。录音库可切换录音与发行；精选及常用入口位于侧栏，保留成员历史并解除旧五星收录门槛。搜索跨实体类型查名称、别名、作品/发行编号、条码、关联人物及派生 Genre。侧栏提供 Genre 树、私人标签、无标签、人物及录制/发行日期筛选；日期未知对象不参与日期区间查询。

作品详情展示作者及相关录音；录音详情展示作品、演出人员与收录发行；发行永远展示全部曲目，任何进入路径都不按作品上下文过滤。详情在右侧展开，主列表收缩，不建立新窗口；关闭、点击列表空白或 Escape 收起后保持列表位置与筛选。窄屏也采用相邻区域，代价是列表会较窄。

新建发行时可添加曲目，已有发行可追加曲目。在曲目详情中“编辑资料”维护具体录音、作品、演出人员及顺序。不会把发行的全部参与者自动写到每个 Track。曲目“播放”单独打开对应音轨或关联录音的音源，不触发详情，也不把打开链接记作真实聆听。

人物/组织档案可填写多个角色，按实际关联显示作品、录音、发行及成员；成员头像网格可打开相应实体。关系日期与来源可编辑，空日期仍保留未知状态。

## 七星评价

仅 Recording 与 Release 有评分编辑。点击七颗星选择，悬停或键盘焦点只预览；“取消评分”选择未评分，点击保存后追加历史。评论可空。两种实体评分独立，0/null 表示无评价，不作为最低质量。

`music_reviews.rating_max` 标识 5 或 7。迁移将原记录标识为五星，保留数值、评论、来源及顺序，不换算。新界面保存七星记录；老五星仍显示原体系，进入编辑时不会默认转换。七星筛选使用 0–7 滑块：0 是未建立七星评价（含未换算的历史五星），1–7 按相应实体七星评分筛选；可单选、选择区间或使用“未评分”。筛选不修改记录。历史五星兼容 API 仍可读写，但不再是顶级资料库入口。

## 聆听

“聆听”独立入口显示时长、次数、历史、按日/周/月统计和按关联作品、录音及人物的次数。事件明确区分手工登记、实际播放、外部导入；迁移前未标类别的历史记为 unknown，避免推断来源。时长未知不估算；关联次数不表示将整张唱片时长分摊给各作品。收藏、打开来源或评分不产生聆听事件。

现有外部事件入口继续用平台与 source_event_id 防重复；未接入新的自动跨平台播放采集器。历史页首批显示最近 100 条，API 支持分页；按日/周/月窗口分别为 90/52/24 期。

## 迁移和恢复

迁移 `0016_music_v070` 仅扩展评分/事件类型、资料及关系表和派生视图；原核心 ID、来源、关联及音乐历史保留。没有 Album→Work 自动转换或姓名去重，没有修改 AI 写入、删除或审核权限。

升级前使用现有 BackupManager 在 `.local/backups` 创建带校验清单的 PostgreSQL 备份，恢复到全新 `shiros_restore_*_test` 数据库并核对数量。在恢复副本额外写入旧代码生成的五星记录，升级后检查值仍为 5/5；对十三张既有数据表按原列生成 SHA-256 指纹，验证迁移没有改写内容。

恢复方案：停止本机工作台和 MCP 写入；保留升级后备份，使用对应 v0.6.1 程序及 `0015_white_theme` 备份清单恢复到独立恢复库，验证后再切换本机数据库配置。不要运行删历史的降级操作，不覆盖现有数据库。备份、密码、个人数据不进入公开源码或安装包。

## 验收与边界

真实 PostgreSQL 自动化覆盖一作品多录音、同录音多发行、完整多作品发行、四乐章单一 Work、Genre 继承与变更、评分保存/清除/体系保留、独立筛选、人物关系和稳定音轨修订。浏览器使用独立测试库的真实工作台 API 验证关联路径、全部曲目、详情收缩、悬停不写入、5→7→未评分、人物头像、聆听空态和桌面/窄屏布局。

资料自动整理候选、联网权威资料补全、自动多平台播放同步、专门的再版组编辑器及内置音频解码播放未在本轮实现。现有外部音源可打开；未将这些限制记为完成。


## v0.7.1 分层浏览补充

左键按人物作品→作品录音→录音发行→发行完整曲目浏览；“详情”单独打开右侧档案面板。返回恢复上层查询、筛选与分页。关联目录依据服务端正式关系，客户端分批读取档案，按当前条件过滤并分页；发行曲目页始终保留全部音轨。发行页和详情各自滚动。历史评价入口读取服务端追加式评价记录，保留原评分体系。音乐和记忆标签管理共用可折叠上级树。


## v0.7.1 档案表单与关联规则补充

新建/编辑按档案类型显示字段，隐藏字段停用 HTML 校验。关联支持搜索、多选及累计添加，角色按主体类型与目标类型限定；作品作者、录音演出人员、发行收录/出版信息及人物组织关系分别维护。作品不直接编辑演出人员，成员/指挥任职在团体档案维护。现有大型作品层级与旧角色关联保留；服务端拒绝新建不适用主体角色，但允许保存同档案已有的旧关联。

发行收藏保存原地更新两处控件，不重建动画按钮。操作错误显示在发生操作的页面/详情/弹窗中，成功反馈不使用错误色。


## v0.7.1 历史评价补充

正常 review 使用系统时间，不接受历史日期。review-history-add 接受不晚于北京时间当天的 historical_date；review-import-preview/review-import 校验 JSON/CSV 的 date、rating、rating_scale、comment，保留文件原始日期与系统录入时间，禁止未来日期，重复文件按对象内导入指纹去重。review-export 输出可再次导入的活动历史评价。

评价展示和当前评分按 coalesce(original_at,created_at) 及 sequence 排序，移除已删除条目后重新确定评分。review-delete 追加 music_review_deletions，不改写 music_reviews；两表保留不可变触发器，导出包含删除记录。迁移 0018_music_review_history 保留原字段和旧版个人记录。档案表单取消个人记录输入，编辑时仍带回已有内容。

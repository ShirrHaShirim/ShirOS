# 对话导入操作说明 · ShirOS v0.7.4

插件已经做好。浏览器扩展与 ShirOS 均更新为 **0.7.4**；无需重新安装 ShirOS 或重新配置数据库。

已在独立 Chrome 中验证项目对话的多容器、消息标记与标题适配；真实 MV3 扩展及批量流程使用独立 Edge 验证。浏览器适配使用合成页面验证，实际账户页面仍需刷新后核对。Codex 内置浏览器未验证扩展安装。

## 已安装扩展：先更新两处

1. Chrome 打开 `chrome://extensions`，找到 **ShirOS Conversation Sync**，点击扩展的重新加载按钮，确认版本为 **0.7.4**。若提示新增网站权限，允许 ChatGPT / DeepSeek；本轮无需重装 ShirOS。
2. 回到 ChatGPT 对话页，刷新网页。这一步会替换仍留在页面里的旧采集器。
3. 打开扩展并点击「开始同步当前对话」。原有单对话配对可继续使用；不必重新填写名称。

扩展目录仍为 `D:\Shir OS\desktop\gpt-sync`。如果原来加载的是别处解压的文件夹，请使用新版 ZIP 替换那个文件夹的内容，再刷新扩展与网页。

## 保存方式和长度

0.7.4 已适配新版 ChatGPT 的 `data-turn-key`、`data-thread-user-message-navigation-content`、`data-markdown-copy` 和 `MarkdownRoot-…`。完整采集的状态依次显示“返回顶部”“顺序读取”“保存”；分别显示提问和回答数量。先确认回到顶部并完成历史加载，再从上到下采集，最后分批保存。只采到提问、没有识别到回答时会提示未完成，不计为完整导入。

再次导出同一对话时，用平台及原始会话编号匹配。新增问答合并到原记忆，保留原来的记忆编号和修订历史；官方导出文件更换文件名也不会另建同一对话的记忆。敏感新增内容仍按正常审核规则处理。

一个会话对应一条记忆，包含按顺序排列的用户与助手消息。后续采集会补充或更新同一条记忆；内部按消息保存并分批传输，不在列表中拆成多条记忆。单条记忆上限为 **1,000 万字符**，新增、编辑、文件导入和 MCP 写入使用同一正文上限。附件原件仍保存到文件库，通过索引关联这条完整对话。

同一次授权中拒绝或删除的内容不会被后续自动同步恢复。要重新导入，应先撤销旧授权，再生成新的平台批量授权并保存新配对信息；新的授权会建立新副本，旧记录的审核与删除状态保留。手动再次选择官方导出文件也属于一次新的导入；仍在库中的同一对话会去重。

## 导入整个导出包中的全部对话

1. 准备从 ChatGPT 下载的官方导出 ZIP，或解压后的 `conversations.json`。
2. 在 ShirOS「文件库」点击「导入全部对话」；设置页也提供同一入口。
3. 选择文件。如果希望拆出 ZIP 内的附件原件，勾选对应选项。
4. 点击「导入全部对话」。每个对话使用原标题，独立保存；一个完整对话对应一条记忆，后续消息更新同一条记录。原导出文件保存在文件库并关联各对话。
5. 完成后显示处理数量、新增/更新、重复、待审和未完成数量。普通内容自动入库；敏感或不确定内容待审，凭据内容会被阻止进入记忆。

相同文件重复导入不会新增同样的记录。单个导入文件最大 50 MB；更大的 ZIP 可先解压再选择 JSON，此方式保留附件引用，不会读取 ZIP 中的原件。即便不勾选拆分附件，所选原 ZIP 本身仍作为一个文件保存。

## 插件批量导入网页对话

1. ShirOS「设置 → 插件与对话同步 → 授权对话」，平台选 ChatGPT，采集范围选「此平台的批量采集」。名称留空即可，也无需逐条粘贴对话地址。
2. 如需附件，单独勾选附件授权，生成配对信息。
3. 在 Chrome 打开 ChatGPT 首页 `https://chatgpt.com/`；将配对信息粘贴到扩展「连接 ShirOS」并保存。不必先打开单个对话。
4. 在首页点击扩展「批量导入对话」。插件会展开收起的侧栏，再处理「最近」中已勾选的「项目」选项，滚动侧栏收集目录，再检查识别到的项目目录页，另开一个后台标签页逐条打开、滚动和保存；保留你当前页面。
5. 查看成功/未完成数量；可点击「停止批量」。关闭弹出面板不会取消任务，浏览器中断则可重新开始。

网页批量包含已发现的项目目录及其可加载的对话；不能保证尚未显示的项目、归档或隐藏记录都在目录里。连续两个对话识别失败会暂停，显示失败项的结构诊断。主动停止时不把当前取消项计入失败。整个账号的完整批量导入请使用上一节的官方导出包。

## ChatGPT / DeepSeek 网页导入

### 1. 保持 ShirOS 运行

使用当前已经配置好的 ShirOS，无需重新安装或初始化数据库。

### 2. 在 Edge 加载现成扩展

1. 打开 Edge，在地址栏输入 `edge://extensions`。
2. 开启「开发人员模式」。
3. 点击「加载解压缩的扩展」。
4. 选择这个文件夹：`D:\Shir OS\desktop\gpt-sync`。
5. 扩展名称是 **ShirOS Conversation Sync**。可在工具栏的扩展菜单中把它固定，方便以后点击。

选择整个文件夹，不要选择其中一个 JS 文件。你当前电脑上已经有该文件夹，无需下载 ZIP。

Chrome 对应的地址是 `chrome://extensions`，其余步骤相同。

### 3. 在 ShirOS 授权这一个对话

1. 在浏览器中登录 ChatGPT 或 DeepSeek，打开要导入的具体对话，复制地址栏中的对话地址。
2. 在 ShirOS 左下角打开「设置 → 插件与对话同步 → 授权对话」。
3. 选择来源平台和「仅一个对话」，粘贴刚复制的对话地址。名称可留空，采集时自动使用网页标题。
4. 网页导入时，「本机会话记录文件」「桌面窗口本机接口」「本机附件目录」都留空。
5. 如果希望保存附件原件，勾选「允许采集此对话的附件原件」。
6. 点击「允许并生成配对信息」，复制生成的整份配对信息。

单对话模式逐条授权，批量模式只需一次明确授权。配对信息包含密钥，只粘贴到自己的插件，不要发到聊天或公开仓库。

### 4. 把配对信息放进扩展

1. 回到刚才的浏览器对话页面。
2. 点击工具栏的 **ShirOS Conversation Sync**。
3. 展开「连接 ShirOS」，粘贴整份配对信息。
4. 点击「保存配对」。

### 5. 开始导入

保持「自动从顶部滚到底部，加载历史」勾选，点击「开始同步当前对话」。插件会回到顶部，等待历史加载，再逐段滚到底部，沿途保存消息；之后继续同步变化。

首次采集时保持该对话页面打开。需要再加载历史时，点击「重新滚动加载历史」。网站没有提供或没有加载出来的消息，插件无法凭空补全。

### 6. 在 ShirOS 查看结果

- 正文：打开「记忆」。
- 需要人工审核的内容：打开「待审」，批准后成为正式记忆。
- 已取得的附件原件：打开「文件库」。
- 文件旁的「关联记忆」可跳转正文；记忆详情中的「关联文件」可下载原件。
- 「仅有引用，原件尚未取得」表示附件尚未下载成功，不代表原件已经保存。

## 停止或更换对话

点击扩展里的「停止」，可停止当前页面采集。到 ShirOS 设置中「撤销授权」，可使该配对失效；已有记忆和文件保留。已撤销项可点击「删除记录」移出列表；勾选「显示已删除的授权记录」后可恢复显示，恢复后的授权仍为撤销状态。删除授权记录不删除已保存的内容。切换对话后会停止，新的对话需要另外授权和配对。

## 桌面客户端怎么导入

| 客户端 | 当前方法 | 是否需要额外插件 |
| --- | --- | --- |
| Codex | 在 ShirOS 授权对应的单个 JSONL 会话记录文件，变化后持续同步 | 这条路线不需要；也已做好可选的 Codex hooks 插件 |
| DeepSeek Harness 正式桌面版 | 同样授权对应的单个 JSONL 会话记录文件 | 不需要浏览器扩展 |
| DeepSeek Harness 浏览器版 | 当前本机对话页面中使用浏览器扩展，或授权会话记录文件 | 网页路线加载上述扩展即可 |
| OpenCode | 使用现成的 `plugins/conversation-sync/opencode.js` 原生插件，并配对会话编号 | 插件已做好，需复制到目标项目或个人插件目录 |
| Windows ChatGPT | 正式客户端的实时窗口采集尚未接通验收；当前先使用网页方案或官方导出文件导入 | 浏览器扩展不能直接安装进 Windows ChatGPT 窗口 |

本机记录文件路线需要准确的会话编号与该会话 `.jsonl` 文件的绝对路径，填到「授权对话」窗口对应字段。允许读取本机附件时，另行勾选附件授权并指定允许的附件目录。ShirOS 不会自动扫描所有会话。

## 仍提示尚未识别消息

先确认扩展和网页都已刷新。展开「识别诊断」，点击「复制识别诊断」提供结果；无需提供正文或配对信息。`extension.manifest`、`extension.popup`、`extension.worker` 和 `current.version` 应均为 0.7.4。诊断包含节点数量、角色计数、滚动阶段、iframe 来源、结构标记及批量失败项，不包含正文。

采集器会等待页面呈现消息，支持同源 iframe 与开放的 Shadow DOM。无法直接读取的跨来源子页面会显示其来源；仅凭 iframe 数量不能判断消息就在里面。若节点仍为 0，使用新版结构诊断继续适配，不应把空对话当作成功导入。

## 已有授权但配对丢失

已有有效配对可直接使用。若再次授权提示已授权，在 ShirOS 设置的授权列表点击「重新生成配对」，粘贴到扩展「连接 ShirOS」并保存。原记忆继续保留，新配对生成后旧配对失效。开始按钮会重新读取当前页面，无效的旧配对记录不会造成空值报错。

如果页面没有实际滚动，新版会停止并提示滚动受阻；提供诊断中的 `current.scroll` 和 `current.scan` 即可，不需要发送正文或配对信息。首次完整读取结束前「已提交 0 条」是正常的，只有确认顶部和末尾后才提交。

0.7.4 支持反向滚动区域。若该页面采用负数坐标，诊断显示 `current.scroll.reversed: true`，原始 `top` 可为负数；`position` 表示从页面顶部算起的位置，供核对顶部和末尾。升级后重新加载扩展并刷新对话页面。

## 已完成采集但记忆列表看不到

插件显示「已保存到 ShirOS」表示正式记录已保存；「已提交 ShirOS 待审」表示可保存的会话内容已在待审草稿中，需在 ShirOS 待审页批准后才显示在一般记忆库。同一对话的后续问答仍更新原记录。

0.7.4 不再因为一条消息触发禁止保存规则而回滚整段。被拒绝消息的原文及附件不写入消息库，只保留未收录占位；插件显示省略数量，其他内容按原顺序提交审核。批准占位记录不会恢复已省略原文。联系人等信息继续脱敏，敏感内容继续待审。

手动选择官方 JSON/ZIP 导入时，原始导出文件仍按该导入窗口的说明保存在文件库，独立于消息库的筛选；文件库原件不等于已批准记忆。浏览器采集不会自动生成或保存这一原始导出包。

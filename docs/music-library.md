# ShirOS Music v0.4.1

打开本机 ShirOS，侧栏选择「音乐库」。这是第二期工程的首个可用版本。

## 使用

1. 「新建」可登记发行、作品、录音、音乐家、乐团和厂牌。关联已存在的档案，而不是把音乐家当作字符串标签。不同录音与发行需要各自建档。
2. 新建发行时可填写曲目，每行 `名称 | 秒数`，未知时长留空。当前曲目列表只在创建时填写；以后可查看、评价、关联音源、登记聆听，不支持重新排序或批量修改。
3. 「评价」保存新的个人评分与评论，保留旧版本。五星是动态视图；五星不会自动进入精选。精选需人工加入，降星后退出符合资格的视图，入选历史保留。常用可手动加入与移出，不自动删减。
4. 「添加音源」绑定 HTTP / HTTPS 链接，通过外部平台打开。不会自动播放或自动统计打开链接。真实听过后可「登记聆听」，实际秒数未知时留空。
5. 「导出档案」下载 `shiros-music-1` JSON，包含音乐关系、标签、评分、成员历史、聆听记录和结构化来源。它是领域档案导出，不是数据库恢复命令；恢复仍使用 PostgreSQL 备份。

## 标签、Genre、图片与配色

音乐侧栏的 Genre 和私人标签均为树形目录，点击父节点包含子分类。通过分类目录「＋」创建子节点、编辑名称或改变父节点。它们使用音乐独立目录，不从记忆标签推断 Genre。

新建档案默认无私人标签，也不强制填写 Genre；“无标签”是筛选条件和清空选择选项，并不是一个实际标签。有 Genre 的档案仍可无私人标签。记忆模块也可在展开全部后的标签视图筛选无标签记忆。

打开专辑、人物或其他档案，点击“导入图片”；已有图片可替换或移除当前引用。支持 JPG、PNG、WebP，最大 8 MiB，最长边规范化至 2048 像素。旧图片保留在历史及导出中，人物 / 乐团使用圆形头像。

右上角“配色”选择羊皮纸、苔庭、青金、暮紫、石墨，立即应用整个 ShirOS，刷新后恢复。配色偏好仅保存在当前浏览器。

## 豆瓣文件导入

支持 UTF-8 CSV（含 BOM）和 JSON 数组 / `{"items": [...]}`。每批最多 1000 条、300000 字符，浏览器 API 请求体上限 400000 字节，大文件应拆批。先预览再确认，任一无效行会拒绝整个批次。

| 标准字段 | 中文 / 其他别名 | 规则 |
| --- | --- | --- |
| douban_id | subject_id / id / 豆瓣ID | 必填，数字 ID；按 scope + ID 去重 |
| title | name / 标题 / 名称 | 必填 |
| status | 状态 | 想听 / 在听 / 听过；亦支持 wish / do / collect、wishlist / listening / listened |
| rating | 评分 | 1–5；空或 null 表示未知，不过滤未评分条目 |
| comment | 短评 | 可选 |
| marked_at | 标记时间 / date | 可选；建议 ISO 日期 / 时间，未知留空 |
| release_year | year / 年份 | 可选，整数年份 |

合成示例见 [music-import-example.csv](music-import-example.csv)。需要将实际豆瓣导出列名映射到上述字段；本版没有豆瓣爬取或自动同步。额外列不进入音乐档案，也不保存原始文件。

首次导入继承评分、短评与三态。再次导入更新豆瓣状态、评分、评论和标记时间；手动评价与已编辑档案不被覆盖，ShirOS 独立聆听状态也不随之后的豆瓣变更自动改变。标题、年份等目录元数据的增量同步尚未实现。重复导入不会产生重复音乐条目或真实播放事件。不同豆瓣 ID 即使同名，也保持为不同发行。

## API / MCP

工作台 `POST /ui-api/music/{action}` 使用现有 loopback、Host、Origin、JSON 请求和浏览器会话 token 防护。actor / scope 在服务端绑定，输入中不接受这两个字段。

读取：`list`、`detail`、`stats`、`export`。写入：`save`、`review`、`membership`、`listen`、`source`、`import-preview`、`import`。Pydantic 请求模型见 `src/shiros/domains/music.py`。已存在对象写入要求 `id` 和当前 `revision`，并发冲突应重新读取；同名不得合并。

MCP 新增 `music_query(action,payload)` 与 `music_mutate(action,payload)`，复用同一服务。Music 写入使用独立的 `music_write` 权限，本版只有本机 owner 拥有。现有 memory editor、reader、proposer 和 worker 不会因此获得音乐写入权；连接中的 AI 可读取授权 scope 的音乐，启用 AI 编辑需后续明确授权与权限管理扩展。普通对话不触发音乐写入。

聆听记录有来源平台事件 ID 时按 scope + platform + source_event_id 去重；相同 ID 的矛盾数据被拒绝，无 ID 的正常重听不会被去重。时长只合计已填的实际秒数，未知时长不按曲目长度估算。

## 当前边界

已实现真实 PostgreSQL 存储与上述 UI、API、MCP；没有将 Mock 当作播放能力。未导入图片的档案使用首字占位，实体信息与过滤为基础实现。会员排序字段已有存储，UI 未提供排序编辑。作品关系可沿详情浏览，支持曲目关联多个作品 / 录音；尚无乐章分组、版本横向比较、实体合并 / 拆分及完整录音元数据编辑。

尚未实现流媒体 OAuth、MusicKit / Spotify 控制、嵌入 / 本地音频播放、统一播放器、跨平台队列、断点续听、历史文件批量导入、计划系统、月度常用规则与报告、MusicBrainz / Discogs 自动补全、逐字段 provenance 与冲突解决。所有音源目前都是外部打开入口，没有验证订阅、地区可用性或平台播放控制能力。

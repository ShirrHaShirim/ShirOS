# 对话同步使用说明 · v0.7.4

在 ShirOS 左下角「设置 → 插件与对话同步」管理授权。默认不采集，可选择单个对话或网页平台的批量范围；对话名称可留空，自动使用原标题。正文保存到一般记忆库，附件原件保存到文件库并建立双向索引。普通内容自动通过，敏感或不确定内容待审，插件不能替你批准。

浏览器扩展、ShirOS 与原生插件版本均为 **0.7.4**。简明操作说明见 `docs/conversation-import-quickstart.md`。

保存结果分为正式保存和待审提交。某条消息禁止保存时，服务端仅记录未收录占位，不保存该消息原文或附件，其余内容继续提交，并保留人工审核。插件和手动导入窗口显示未收录数量。手动导入的原始导出文件仍按文件库原件功能保存，不会因消息筛选被自动修改。

## 支持范围

| 来源 | 接入方法 | 当前验证范围 |
| --- | --- | --- |
| ChatGPT 网页 | Edge/Chrome 浏览器扩展 | 独立 Chrome 项目页合成布局与工作台验证；实际 Edge MV3 扩展及批量运行验证；私人账户页面未实机读取 |
| DeepSeek 网页 | 同一浏览器扩展 | 已有页面适配；未用真实账户对话验收 |
| Codex | 已授权的单个 JSONL 记录文件；或本地插件 hooks | 文件接入和 hooks 端到端合成测试通过 |
| OpenCode 桌面/终端 | OpenCode 原生插件读取已配对会话 | 官方插件事件及消息 SDK 接口；合成客户端和真实 ShirOS 接收端验证 |
| DeepSeek Harness 浏览器 | 扩展在本机页面手动开始；或选择会话 JSONL | 使用现有 DSH 消息节点结构和记录格式 |
| DeepSeek Harness 正式桌面 | 选择对应会话 JSONL 文件 | v0/v3 记录形状核对，增量更新和流式文本归并测试通过 |
| Windows ChatGPT | 可选本机窗口接口 | **条件适配：仅当客户端已经提供本机调试接口时可用；正式 Windows 客户端尚未接通验收。** 无此接口时使用网页扩展或官方导出导入 |

Windows ChatGPT 与 DeepSeek Harness 桌面版是不同客户端。没有重新安装它们，也没有修改它们的启动参数或重启当前聊天应用。

## 网页扩展

1. 打开 Edge 的 `edge://extensions` 或 Chrome 的 `chrome://extensions`，开启开发人员模式。
2. 点击「加载解压缩的扩展」，选择项目的 `desktop/gpt-sync` 文件夹，或解压 `desktop/plugin-packages/shiros-browser-sync-0.7.4.1.zip` 后选择对应文件夹。已有扩展要重新加载，然后刷新对话网页。
3. 在 ShirOS 设置中点击「授权对话」，选平台和范围；单对话填写地址，批量范围不用逐条填写地址，名称均可留空。需要保存原件时另行勾选附件授权。网页扩展无需填写本机记录文件或窗口接口。
4. 复制新生成的配对信息，在扩展面板「连接 ShirOS」粘贴并保存。配对信息包含授权密钥，只放在自己的插件或本机配置中。
5. 打开对应对话，点击「开始同步」。默认开启「自动从顶部滚到底部，加载历史」，之后持续同步变化。也可以随时点击「重新滚动加载历史」。
6. 点击「停止」可停止当前网页采集；「停止批量」停止批量任务。在 ShirOS「撤销授权」可使配对立即失效。单对话模式切换页面会停止，批量授权可用于同平台的其他对话。

批量按钮处理「最近」的「项目」过滤选项后滚动目录，检查发现的项目目录页，再通过单独的后台标签页逐条进入对话、加载和保存。保留原标签页，显示项目检查数、成功与未完成数量，支持停止。连续两个识别失败会暂停；用户停止不额外计算失败。网页可加载的目录不等于整个账号，未显示的项目、归档或隐藏链接可能遗漏。

**全部导出文件导入：**文件库或设置里的「导入全部对话」接受官方 ZIP / conversations.json，按对话分别建立记忆，一个完整对话对应一条记忆，后续消息更新同一条记录，保留原标题、原始时间和导出中的消息分支，原导出文件关联到记忆。可另外允许拆出 ZIP 中能唯一匹配的附件原件；找不到的原件仅记录引用。重复同一文件不会新增同样记录。原 ZIP 本身会作为文件保存，与是否拆出附件无关。最大 50 MB，较大的 ZIP 请解压后选择 JSON。

自动滚动会先回到顶部，等待历史加载，再分段滚动到底部，沿途累计消息，因此页面只保留当前可见消息时也可以保存经过的消息。页面仍需保持打开；若网站没有加载更早消息、被登录限制或未提供可识别的消息节点，插件不会宣称已取得完整历史。顶部和底部加载都有次数上限，防止无限滚动；可再次点击重新滚动。

DeepSeek Harness 等本机页面没有预置站点权限：打开扩展面板后，通过当前标签页权限注入采集器，再为该会话配对。OpenCode 优先使用原生插件。

## 本机记录文件

在授权窗口选择平台、填写准确的会话编号，并填写**该会话的单个 `.jsonl` 或 `.json` 文件绝对路径**。允许后，ShirOS 每约两秒检查此文件的变化。不会扫描整个会话目录。

Codex 和 DSH 记录中的会话编号必须与授权匹配。源文件仍是原件，ShirOS 只读取，不改写。不收集隐藏推理字段。生成中尚未写完的最后一行会留待下次读取；格式损坏会提示同步未完成。

需要读取记录里引用的本机附件时，勾选附件授权并填写允许的附件目录。目录外文件及链接、目录联接不会被读取。没有允许目录或无法取得原件时，仅保留附件引用。

ChatGPT 官方导出文件请使用「导入全部对话」。导出文件不会自行持续更新，因此不等同于 Windows 客户端实时接入。原有文件导入接口为兼容保留，界面使用新的记忆与文件联合导入路径。

## Codex 本地插件

插件源码位于 `plugins/conversation-sync`，交付 ZIP 位于 `desktop/plugin-packages/conversation-sync-0.7.4.zip`。安装本地插件后，客户端仍须允许其 hook 定义。安装插件本身不等于授权所有对话。

将设置页生成的配对 JSON 保存到本机 `~/.config/ShirOS/capture.json`；多个对话使用 `{"pairings":[第一份配对,第二份配对]}`。也可用 `SHIROS_CAPTURE_CONFIG` 指定自己的配置路径。hook 使用配对信息中的现有 ShirOS Python 运行环境；外层 hook 命令需要本机 Python 可用。

只有当前会话编号与配对一致时，插件才读取 hook 提供的记录文件。在提交消息和完成回复时同步。若希望生成过程中也持续更新，使用上一节的单文件同步方式。hook 失败不会阻断聊天，也不会把对话正文或密钥打印到日志。

Codex 会话记录格式不是稳定协议，未来升级可能需要适配。[官方 hooks 说明](https://learn.chatgpt.com/docs/hooks) 和 [插件打包说明](https://developers.openai.com/plugins/build/plugins)。

## OpenCode 原生插件

把 `plugins/conversation-sync/opencode.js` 复制到目标 OpenCode 项目的 `.opencode/plugins/shiros-capture.js`，或自己的 `~/.config/opencode/plugins/shiros-capture.js`。按官方插件机制，在下一次启动时加载；本轮没有替你修改全局插件目录。

配对配置与 Codex 使用同一位置，但平台应选 OpenCode，编号使用准确的 OpenCode session ID。消息更新后约两秒同步，会话空闲时立即同步。未配对会话不会调用消息读取接口。

参见 [OpenCode 插件说明](https://docs.opencode.ai/docs/plugins/) 与 [消息 SDK](https://opencode.ai/docs/sdk/)。

## 附件、修订和撤销

- 已取得原始字节的附件才进入文件库；缺失原件显示「仅有引用，原件尚未取得」。网页中允许的同源下载、Blob 原件及开启同步后选择的上传文件可被读取。跨站下载链接、需额外下载步骤的文件不会自动获取。
- 文件库中的同步附件有「关联记忆」按钮；记忆详情有「关联文件」和下载按钮。待审内容批准后，索引自动对应正式记忆。删除原件后，关联会显示「原件已删除」。
- 相同消息重复采集不会重复入库；文本变化会修订原消息。敏感修订继续待审，不会绕过审核。已拒绝、撤销来源或不可见记忆不会被自动恢复。
- 网页提供稳定消息编号时，可准确修订原消息。未提供编号的页面使用内容快照标识，变化可能形成单独快照；不能据此承诺完整区分重复文本或消息编辑。原生记录和 SDK 接入优先保留消息编号。
- 撤销授权会停止新写入，已保存记忆和文件保留。网页上的「停止」控制当前采集，服务端撤销控制授权本身。
- 已撤销的授权记录可以删除；在「显示已删除的授权记录」中可以恢复显示。授权、采集索引和审计保留，已有记忆与文件不受影响，恢复显示不重新授权。
- 已保存消息不会因为源页面后来隐藏、删除或缩短消息而自动删除。单条记忆最多保存 1,000 万字符；消息分批传输并在服务端合成完整对话；一次选定记录文件最多 50 MB、10,000 条消息，单个附件最大 50 MB。

## 验证与排障

先用不含私人信息的短对话测试：授权、开始、查看记忆、下载附件、查看反向关联，再停止并撤销。设置页显示最近同步时间或失败代码。

如果无法识别消息，先重新加载扩展并刷新网页；确认诊断版本为 0.7.4、当前编号与授权一致及 ShirOS 正在运行。新版覆盖项目地址、多容器、通用消息节点、作者标题、同源 iframe、开放的 Shadow DOM 和延迟呈现。开始前先核对服务端授权，未通过时不读取消息。

「复制识别诊断」提供当前页和批量失败页的节点数量、子页面来源、结构标记与跳过计数，不包含正文。跨来源 iframe 仅报告来源，不能据此承诺已经读取其内容。不要把密钥或真实对话粘贴到日志。浏览器扩展不能直接注入 Windows ChatGPT 独立窗口。

## 完整会话与首页入口

### 批量接收与目录发现修正

本轮修复运行数据库缺少 `capture_entries.archived` 导致的接收失败。升级采用新增迁移 `0023_capture_schema_repair`，兼容此前两种数据库状态，保留原有记录；健康检查同时检查字段与索引，避免只核对迁移编号。

扩展会读取多个滚动列表、合并项目筛选两种状态、展开可见的更多列表、读取搜索目录，并继续遍历页面提供的项目及目录链接。计数显示“已发现”；目录超时、到达保护上限或读取失败会提示未完成。它不能保证获得网页未提供的归档等记录；需要整个账号的完整记录时，可导入官方导出包。

非 JSON 错误会显示 HTTP 状态，暂时错误最多尝试三次；持续失败暂停批量，已保存内容保留。页面接收器断开时会尝试重新注入，无法访问网站时明确提示扩展权限。重新加载扩展并刷新网页后生效；无需重新配对，已撤销的授权须另行重新授权。

### 新版 ChatGPT 消息适配 · 0.7.4

根据用户提供的结构诊断，消息标记已改为 `data-turn-key`、`data-thread-user-message-navigation-content`、`data-markdown-copy`、`MarkdownRoot-…`。采集器支持这些标记，提问与回答按各自角色识别；同一轮中的两种消息使用独立稳定编号，避免覆盖。

滚动优先选择真实对话容器，覆盖 `data-app-action-timeline-scroll` 与嵌套滚动区域。流程依次为等待消息、回到顶部并等待较早历史稳定、向下分段读取、保存。滚动过程中积累内容，完成后分批提交，减少重复修订。未能确认顶部或底部、或者只识别到提问而没有回答时，不标记为完整成功。代码正文保留，输入框草稿、标题栏和操作按钮不作为消息导入。

批量目录在独立标签页执行，保留用户的原页面；目录链接识别不依赖 nav/aside。再次采集或再次选择官方导出文件时，根据平台与原始会话编号合并新问答到原记忆，保留记忆编号和修订历史；仍按正常敏感内容审核规则处理。

诊断包含扩展 manifest、弹窗、后台及页面采集器四个版本。升级后重新加载扩展并刷新页面，四项应均为 0.7.4。真实账户的全量范围仍取决于网页提供的目录，官方导出包导入用于覆盖导出文件中的全部对话。

每个会话在一般记忆库中对应一条完整记录；消息按顺序合并，后续消息、正文修订和历史补载更新同一条记忆。正文存储上限扩展至 1,000 万字符，列表只返回预览，详情和 Markdown 导出读取完整正文；搜索与模型上下文继续保持有界。

打开 `https://chatgpt.com/` 后，扩展直接提供「批量导入对话」。首页隐藏单对话同步控件，批量任务会展开收起的侧栏，发现最近列表、项目目录和其中的会话，在独立标签页逐条加载与保存。只需首次在 ShirOS 创建平台批量授权并保存配对。

相同授权继续遵守已有的拒绝、删除决定。撤销旧授权并建立新授权后，可重新采集为新的副本，旧审核及删除状态保留。再次手动选择官方导出文件也会建立新的导入授权；有效的现有会话仍去重。自动保存不恢复被拒绝或已撤销的旧副本。
# 标题格式修正 · 浏览器扩展 0.7.4.1

新导入会话统一为 `对话｜原会话主题｜完整对话`，与正文记录类型一致；已按三段式命名的会话保留领域及主题。Chrome 弹窗显示记忆标题预览。已有会话继续更新原记忆，保留人工修订的标题。请在 `chrome://extensions` 重新加载原扩展目录并刷新对话页面。
